理解 LLM 的核心骨架

ChatGPT、Gemma、Claude 外表不同，骨架相近： 文字 → Token → Transformer／Attention → 機率分布 → 下一個 Token → 重複。 下面用你熟悉的「TP 知識庫」比喻，少算式、多圖解。

跳到六個旋鈕
A

先給你一張總地圖

先記住這條鏈；後面每一節都在拆它。

文字 → Token → Transformer → Attention → 機率分布 → 下一個 Token → 重複…

Transformer 不是答案資料庫；它是很會處理「各個 Token 彼此關係」的神經網路架構。真正「查 TP 法規原文」靠的是你的 RAG／知識庫。

文字輸入後進入文字星雲，進行神經突觸連結與機率推演。

01

Token 是什麼？

LLM 通常不把整句當「一個單位」處理，而是先切成 Token。

中文例

受測個體應如何選擇？

Token ≠ 一定等於一個中文字；怎麼切取決於 tokenizer。

英文例

Transfer pricing report

一個英文單字可能是 1～數個 token。

記住：Token = LLM 處理文字時的基本單位。

02

Token 變成什麼？→ Embedding

Token 先是編號；編號再變成一串數字（向量）——數學上的「意思座標」。

Token 受測
→
ID 18372
→
向量 [0.12, -0.31, 0.82, …]

相近意思的詞，在向量空間裡往往較靠近——這也是 RAG 用 Embedding 做向量搜尋的基礎。

03

Transformer 與 Attention

Transformer＝很會分析句子裡 Token 關係的架構；Attention＝「現在該注意哪些 Token？」

代名詞要靠上下文

「小明把報告交給主任，他要求修改。」——「他」是誰？

TP：「受測個體應選擇功能較單純之一方，並考量其承擔之功能及風險。」——「其」指誰？

模型必須看：受測個體 ↔ 其。這正是 Transformer 擅長的事。

為什麼叫 Attention？

像人閱讀：看到「他」會回頭看小明、主任、報告、錯誤，再判斷指誰。

Attention＝在一大堆資訊裡，找出現在最值得注意的部分——不是平均看每個字。

互動：點一個 Token，看它「注意」誰

點上方 Token 試看看。

04

機率分布：不是「查答案」，是「猜下一個 Token」

某種程度上 ChatGPT 確實是一直預測下一個 Token——但預測前已用 Attention 消化整個上下文。

Context：受測個體應選擇功能較

選出「單純」→ 再以新句子當 Context，重複整段流程。答案是一個 Token 一個 Token 長出來的。

「只是在猜下一個字」容易低估模型：猜之前，內部表示與 Attention 已經很複雜。

05

六個旋鈕：Context／Reranker／Temperature／Top-K／Top-P／Fine-tuning

懂了骨架之後，這些參數就只是在管「餵多少、挑什麼、怎麼抽樣、要不要改性格」。

使用者問題
    ↓ Token
    ↓ Context Window ← 一次最多能看多少
    ↓ RAG／Vector Search
    ↓ Reranker ← 哪些資料最值得給 LLM
    ↓ Transformer + Attention
    ↓ 機率分布
    ↓ Temperature ← 穩定 vs 有變化
    ↓ Top-K／Top-P ← 允許從哪些候選選
    ↓ 輸出答案

1. Context Window＝工作記憶

一次能塞進的 Token 總量：系統提示＋問題＋RAG＋歷史＋輸出預算，大家一起搶。

你調 Chunk Size、Top-K、Context Length，本質是在管「餵多少 TP 知識給模型」。

2. Reranker＝第二輪裁判

向量相似 ≠ 最能回答問題。先寬抓，再精準挑——法令／OECD 尤其需要。

Vector Top-10
    → Rerank →
    留給 LLM 的 Top-5

      3–5. Temperature · Top-K · Top-P（抽樣）

      三者都作用在「機率分布 → 選出下一個 Token」這一步。拖動旋鈕看候選怎麼變。

      低溫＋適度 Top-K／P → 查核語氣較穩；高溫 → 較多變化（也較易飄）。

      Top-K：固定留前 K 名
      Top-P：從高到低加總到累積機率 P
      Temperature：把分布變尖（穩）或變平（隨機）

      6. Fine-tuning vs RAG

      RAG

      給模型可查的資料（準則、OECD、函釋）。知識更新＝改知識庫。

      Fine-tuning

      用大量「問題→專業答案」教模型回答方式／風格。比較像改性格與格式習慣。

      做 TP 助理：多數情況先把 RAG＋Reranker＋低溫做好；Fine-tuning 是加分，不是第一步。

      06

      接回你的 TP／RAG 系統

      外部找資料（Embedding＋搜尋＋Rerank）＋內部理解生成（Transformer＋機率）。

      ★

      最後用一句話記住

      把整套 LLM 收成這句，之後看參數就不會散。

      Token 是「字」；Embedding 是「把字變成數學表示」；Attention 是「現在該注意哪些字」；Transformer 是「處理這些關係的神經網路」；機率分布 是「下一個 Token 各有多大可能」。

      接回 RAG：Embedding＋向量搜尋＝去外部知識庫找資料；Transformer＋Attention＝把找到的資料和問題一起理解；Token＋機率＝一個字一個字長出答案。
